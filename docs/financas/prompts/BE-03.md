## Tarefa
1. Validators (exportar em `validators/index.ts`):
   - `contas-pagar.validator.ts`: `competenciaSchema` (`/^\d{4}-(0[1-9]|1[0-2])$/`); `contaPagarInsertSchema` (`descricao` 1–500, `categoria` 1–100 default `'Contas'`, `valor` positivo, `recorrencia` `mensal|anual|unica`; `dia_vencimento` 1–31 se mensal/anual, `mes_vencimento` 1–12 só se anual, `data_vencimento` `yyyy-MM-dd` só se única — mesmo CHECK da SPEC 4); `pagarContaSchema` (`competencia`, `pago_em` `yyyy-MM-dd` opcional, `banco` ≤100 nullable opcional);
   - `rendas.validator.ts` (`descricao`, `valor` > 0, `dia_recebimento` 1–31 opcional, `ativo`);
   - `orcamento.validator.ts` (`categoria` 1–100, `valor_planejado` ≥ 0);
   - `push-subscription.validator.ts` (`endpoint` URL https, `keys.p256dh`, `keys.auth` não vazios, `user_agent` opcional).
2. Repositories (exportar no barrel):
   - `contasPagarRepository`: `findAll(userId, { ativo? })`, `findById(id, userId)`, `findByAssinatura(assinaturaId, userId)`, `create`, `update(id, data, userId)`, `rpcPagar(contaId, competencia, pagoEm?, banco?)`, `rpcDesfazer(contaId, competencia)`;
   - `pagamentosContaRepository`: `findByCompetencia(userId, competencia)`, `findByConta(userId, contaId)` (histórico, mais recente primeiro). Escrita só pelas RPCs;
   - `rendasRepository`, `orcamentoRepository` (CRUD por `userId`; orçamento com upsert em `user_id,categoria`);
   - `pushSubscriptionsRepository`: `upsertByEndpoint(userId, sub)`, `removeByEndpoint(userId, endpoint)`;
   - funções do cron, nomeadas `*ParaCron` e recebendo o client admin por parâmetro: `contasAtivasComInscricaoParaCron(client)`, `pagamentosDasCompetenciasParaCron(client, competencias)`, `inscricoesDoUsuarioParaCron(client, userId)`, `removerInscricaoParaCron(client, id)`, `reservarLembreteParaCron(client, row)` (insert com `ignoreDuplicates`, retorna `true` só se inseriu).
   **Toda query de usuário filtra `.eq('user_id', userId)`.**
