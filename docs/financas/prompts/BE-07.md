# Codex — BE-07: Web Push no servidor + rota de cron dos lembretes

## Contexto
Depende do BE-01, BE-03 e BE-04. Regras nas seções 5.3, 6 e 7 da `docs/financas/SPEC.md`: às 09h de Brasília (Vercel Cron às 12:00 UTC) cada conta `pendente` recebe D-2 "Vence em breve", D-1 "Já foi pago?" e D0 "Tá tudo certo?", no máximo uma vez por (conta, mês, etapa, canal). Conta paga não recebe mais nada. O `sw.js` e a UI de inscrição são do FE-06.

## Leia
- `docs/financas/SPEC.md` (seções 5.1, 5.3, 6, 7, 8)
- `apps/web/app/api/delete-account/route.ts` (padrão de client service role no servidor)
- `packages/api/src/repositories/*ParaCron` e `push-subscriptions` (BE-03), `services/contas-pagar.service.ts` (BE-04)

## Tarefa
1. `packages/api/src/services/lembretes.service.ts` → `enviarLembretesDoDia({ client, sender, hojeISO = hojeSP() })`:
   - gera as ocorrências do mês de `hoje` e do seguinte para usuários com inscrição;
   - busca contas `pendente` com vencimento em `[hoje, hoje+2]`, calcula `etapaLembrete`;
   - **reserva** com `reservarLembreteParaCron` (canal `'push'`) e só envia se reservou;
   - envia para todas as inscrições do usuário com o payload da SPEC 5.3 (`LEMBRETE_TEXTOS`, valor em pt-BR, `url: /financas/contas/<id>`); 404/410 → remove a inscrição; outros erros só logam (sem endpoint, chaves, nome ou valor da conta);
   - retorna `{ contas, enviados, ignorados, inscricoesRemovidas }`.
   `sender` é uma interface (`send(sub, payload) => Promise<{ statusCode }>`); a implementação real usa `web-push` com `VAPID_SUBJECT`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` lidos de `process.env` (falha explícita se faltarem; sem fallback hardcoded).
2. `apps/web/app/api/cron/lembretes/route.ts` (`GET`, `runtime = 'nodejs'`, `dynamic = 'force-dynamic'`): compara `Authorization` com `Bearer ${process.env.CRON_SECRET}` (401 se ausente/diferente, inclusive se a env não existir), cria o client admin e chama `enviarLembretesDoDia`. Responde só os contadores.
3. `apps/web/app/api/push/subscribe/route.ts`: `POST` (valida com o validator do BE-03, `upsertByEndpoint` com o `user_id` da sessão) e `DELETE` (remove por endpoint). 401 sem sessão.
4. **Não criar job real**: não alterar `vercel.json`. No PR, incluir o trecho `{"crons":[{"path":"/api/cron/lembretes","schedule":"0 12 * * *"}]}` e a alternativa `pg_cron` + `pg_net` (só texto) para o Estevam habilitar.
