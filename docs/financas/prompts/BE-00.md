# Codex — BE-00: Validar `000_baseline.sql` e documentar os gaps de schema

## Contexto
Monorepo MeuDia (Next.js + Supabase). `packages/database/migrations/001_initial_schema.sql` agora tem o SQL do schema.sql inline (antes usava `\i`). Foi criado `packages/database/migrations/000_baseline.sql`, idempotente, que recria schema.sql + 002 + 003 + 004. O cabeçalho dele lista os gaps GAP-01 a GAP-09 (GAP-01, 02, 05, 06 e 07 resolvidos; GAP-04 parcialmente: trigger `updated_at` em `notas`).

Nomes canônicos (decididos, usados em todo o repo): `registros_agua` (já existe no banco), `registros_habito`, `registro_medicamentos`, `itens_compras`, `scores_diarios`, `conquistas`.

`registros_agua` usa as colunas do banco: `id, user_id, data, quantidade_ml INTEGER NOT NULL DEFAULT 0, meta_ml INTEGER NOT NULL DEFAULT 2500, created_at, updated_at` (a UI converte copos com `AGUA.ML_POR_COPO = 250`). Ela tem um DO block próprio que garante `users_own_data` e cobertura de SELECT/UPDATE/DELETE.

## Leia
- `packages/database/migrations/000_baseline.sql` (cabeçalho inteiro)
- `packages/database/schema.sql`, `packages/database/migrations/00{2,3,4}_*.sql`
- `packages/api/src/repositories/*.repository.ts`, só as chamadas `.from('...')`

## Tarefa
1. Num Postgres/Supabase **local e descartável** (`supabase start`, ou um container com schema `auth` stub com `auth.users` e `auth.uid()`), rode `000_baseline.sql` duas vezes. Registre os NOTICEs.
2. Repita num banco em que `public.registros_agua` (colunas acima) já exista antes do baseline, com RLS e **só** a policy `Users can insert own registros_agua` (FOR INSERT). Confirme que a tabela não é alterada, que depois do baseline SELECT/UPDATE/DELETE estão cobertos para o dono (e negados para outro usuário) e que a 2ª execução não cria policy nova.
3. Confirme que `UPDATE public.notas` atualiza `updated_at` (trigger `trg_notas_updated_at`) e que o trigger não é duplicado.
4. Escreva `docs/financas/SCHEMA_GAPS.md` confirmando que schema.sql, 001, 004, seeds, queries e `.from('...')` usam só os nomes canônicos e as colunas `quantidade_ml`/`meta_ml` (arquivo:linha de qualquer exceção) e listando gaps restantes com risco e recomendação. **Não renomeie tabela nenhuma.**
5. Se encontrar erro de sintaxe/idempotência no baseline, corrija o mínimo e explique no SCHEMA_GAPS.md.
