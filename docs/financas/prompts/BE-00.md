# Codex — BE-00: Validar `000_baseline.sql` e documentar os gaps de schema

## Contexto
Monorepo MeuDia (Next.js + Supabase). `packages/database/migrations/001_initial_schema.sql` só faz `\i ../schema.sql`, o que não funciona no Supabase. Foi criado `packages/database/migrations/000_baseline.sql`, idempotente, que recria schema.sql + 002 + 003 + 004. O cabeçalho dele lista os gaps GAP-01 a GAP-09.

## Leia
- `packages/database/migrations/000_baseline.sql` (cabeçalho inteiro)
- `packages/database/schema.sql`, `packages/database/migrations/00{2,3,4}_*.sql`
- `packages/api/src/repositories/*.repository.ts`, só as chamadas `.from('...')`

## Tarefa
1. Num Postgres/Supabase **local e descartável** (`supabase start`, ou um container com schema `auth` stub com `auth.users` e `auth.uid()`), rode `000_baseline.sql` duas vezes. Registre os NOTICEs.
2. Repita num banco em que `public.registros_agua(id, user_id, data)` já exista antes do baseline e confirme que `registro_agua` não é criada.
3. Escreva `docs/financas/SCHEMA_GAPS.md` com uma tabela para cada um dos 6 pares do GAP-02: nome no schema.sql, nome no 004, nome usado no código (arquivo:linha), risco, recomendação. **Não renomeie nada e não escolha o nome canônico.** Só recomende.
4. Se encontrar erro de sintaxe/idempotência no baseline, corrija o mínimo e explique no SCHEMA_GAPS.md.

## Restrições
- PROIBIDO aplicar em banco remoto/produção, `supabase db push`, `supabase link`, redeploy.
- PROIBIDO ler, imprimir ou alterar `.env*` ou qualquer segredo.
- PROIBIDO `git commit` / `git push`.

## Critérios de aceite
- [ ] 2 execuções seguidas sem erro; a 2ª não cria objetos novos (comparar `pg_tables`, `pg_indexes`, `pg_policies` antes e depois).
- [ ] O cenário com `registros_agua` preexistente emite NOTICE do GAP-02 e não cria `registro_agua`.
- [ ] `SCHEMA_GAPS.md` criado com os 6 pares e as evidências.

## Entrega
Lista de arquivos alterados e trecho dos NOTICEs da 1ª e da 2ª execução.
