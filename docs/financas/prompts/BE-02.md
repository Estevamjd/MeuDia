# Codex — BE-02: Migration `005_financas.sql` + tipos compartilhados

## Contexto
MeuDia Finanças. Modelo de dados na seção 4 da `docs/financas/SPEC.md` e RPCs na 4.1. `contas_pagar` é a **definição** da conta (mensal/anual/única), sem status por mês; cada pagamento é uma linha em `pagamentos_conta`, única por `(conta_id, competencia)` com competência `TEXT 'YYYY-MM'`; `pagar_conta`/`desfazer_pagamento` recebem a competência e criam/apagam o pagamento e a despesa em `transacoes`. `assinaturas` não ganha colunas (só a `UNIQUE (id, user_id)` para a FK do espelho `contas_pagar.assinatura_id`). O padrão de idempotência e RLS é o de `packages/database/migrations/000_baseline.sql`, que já define `public.set_updated_at()`. **Só arquivo**: nada é aplicado sem o OK do Estevam.

## Leia

## Tarefa
1. `packages/database/migrations/005_financas.sql`:
   - DO block: `UNIQUE (id, user_id)` em `assinaturas` e `transacoes` (só se a constraint não existir em `pg_constraint`);
   - `CREATE TABLE IF NOT EXISTS` `contas_pagar`, `pagamentos_conta`, `rendas`, `orcamento_categorias`, `push_subscriptions`, `lembretes_enviados` exatamente como na SPEC, com índices `IF NOT EXISTS` (único parcial `contas_pagar(assinatura_id)`, `pagamentos_conta(user_id, competencia)`, único `lembretes_enviados(conta_id, competencia, etapa, canal)`);
   - `contas_pagar`: CHECK de coerência `recorrencia` × `dia_vencimento`/`mes_vencimento`/`data_vencimento`, `ativo`, `UNIQUE (id, user_id)`; **sem** `status`/`pago_em`/`competencia`;
   - `pagamentos_conta`: `competencia TEXT` com CHECK `competencia ~ '^[0-9]{4}-(0[1-9]|1[0-2])$'`, `pago_em DATE NOT NULL`, `transacao_id` opcional, `UNIQUE (conta_id, competencia)`; mesmo CHECK em `lembretes_enviados.competencia`;
   - **FK compostas `(id, user_id)`**: `contas_pagar(assinatura_id, user_id) → assinaturas ON DELETE SET NULL (assinatura_id)`; `pagamentos_conta(conta_id, user_id) → contas_pagar(id, user_id) ON DELETE CASCADE`; `pagamentos_conta(transacao_id, user_id) → transacoes ON DELETE SET NULL (transacao_id)`; `lembretes_enviados(conta_id, user_id) → contas_pagar(id, user_id) ON DELETE CASCADE`. Comente no SQL o porquê (impede referenciar linha de outro usuário; a lista de colunas no SET NULL evita zerar `user_id`);
   - `ENABLE ROW LEVEL SECURITY` em todas (inclusive `pagamentos_conta`) + `users_own_data` (`FOR ALL USING/WITH CHECK auth.uid() = user_id`) em DO block; em `lembretes_enviados`, só policy de SELECT para o dono;
   - triggers `updated_at` com `public.set_updated_at()` em `contas_pagar`, `rendas`, `orcamento_categorias` (criados só se não existirem);
   - `CREATE OR REPLACE FUNCTION public.pagar_conta(p_conta_id uuid, p_competencia text, p_pago_em date DEFAULT NULL, p_banco text DEFAULT NULL) RETURNS public.pagamentos_conta`: `LANGUAGE plpgsql SECURITY INVOKER SET search_path = public`, `SELECT ... FOR UPDATE` da conta, valida a competência contra a recorrência (SPEC 4.1 passo 2), `RAISE EXCEPTION` se já houver pagamento na competência, `pago_em = coalesce(p_pago_em, (now() AT TIME ZONE 'America/Sao_Paulo')::date)`, INSERT em `transacoes` (`automatico=true`, `user_id` da conta), INSERT em `pagamentos_conta` e retorno;
   - `CREATE OR REPLACE FUNCTION public.desfazer_pagamento(p_conta_id uuid, p_competencia text) RETURNS void`: `FOR UPDATE` no pagamento, `RAISE EXCEPTION` se não existir, apaga a transação vinculada e o pagamento.
2. `005_financas_down.sql`: drop das funções, triggers, tabelas novas e constraints adicionadas (`IF EXISTS`). Não dropar `set_updated_at` (é do baseline).
3. Tipos/constantes em `@meudia/shared` (SPEC 8): `Competencia`, `Recorrencia`, `ContaPagar`, `ContaPagarInsert`, `PagamentoConta`, `SituacaoOcorrencia`, `OcorrenciaConta`, `Renda`, `OrcamentoCategoria`, `PushSubscriptionRow`, `LembreteEnviado`, `Selo`, `SELO_LIMITES`, `LEMBRETE_TEXTOS`.
